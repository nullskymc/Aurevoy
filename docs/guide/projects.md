# 项目与工作台

**项目**把对话绑到本地目录，让文件工具有明确边界，并在工作台中浏览改动。  
**独立对话**不绑目录，适合一次性调研或与仓库无关的写作。

## 为什么要先选项目

Agent 文档与实践里反复出现的一点：很多质量问题其实是**工作目录不对**。  
口头说「就在这个仓库」不如在 UI 里导入该文件夹来得可靠。

适合导入项目的场景：

- 功能开发、重构、修 bug  
- 仓库内批量改文件  
- 需要对照文件树与 diff 审查  

可以保持独立对话的场景：

- 纯概念问答  
- 与本地文件无关的短文  
- 尚未决定落在哪个目录的探索  

## 导入与切换

1. 侧栏打开 **项目**  
2. **导入项目**，选择文件夹（通常是仓库根）  
3. 在该项目下 **新对话**，或从列表进入已有对话  

删除项目时：对话记录不会被强制抹掉，但会变成**独立对话**（不再挂在该项目下）。

## 工作台

工作台用于：

- 浏览工作区文件树  
- 打开预览或源码  
- 查看对话产物  
- 把路径类结果与主对话对照  

可随时隐藏，专注阅读交付内容。与输出面板在布局上互斥，避免叠在对话上。

使用建议：

- Agent 声称改了某文件 → 在工作台打开核对  
- 大改前自己先 `git status` / 建分支  
- 删除、重命名触发审批时，对照文件树路径再点允许  

## 在目标里怎么写路径

即使已绑定项目，仍建议写清子范围：

```
在当前项目中，仅修改 packages/web-ui 下与设置页相关的文件。
不要改 apps/agent。
```

跨仓库任务：开对应项目下的对话，或明确绝对路径；不要假设 Agent「记得」上一个项目。

## 项目 vs 知识库

| | 项目工作区 | 知识库 |
|---|---|---|
| 目的 | 当前要操作 / 修改的目录 | 检索资料与文档 |
| 交互 | 工作台 + 文件工具 | 索引后召回片段 |
| 典型说法 | 「在当前项目实现…」 | 「根据知识库里关于发布的文档…」 |

可以同时用：项目负责动手，知识库负责查阅。见 [记忆与知识库](./memory)。

# 记忆与知识库

两类「记住」机制用途不同：

| | 长期记忆 | 知识库 |
|---|---|---|
| 形态 | 短条目（偏好、事实、习惯） | 目录内文档分块索引 |
| 写入 | 你手动添加，或 Agent 记录后你可审阅 | 添加目录并索引 |
| 典型用途 | 「用简洁中文」「常用目录在…」 | 「根据这批规范 / 笔记回答」 |
| 失败降级 | 可无向量仍保留条目 | 无 Embedding 时语义检索变弱，可降级关键词 |

## 长期记忆

### 该记什么

- 稳定偏好：语言、回复结构、代码风格倾向  
- 常用事实：主项目路径、命名约定、账号无关的环境说明  
- 习惯：提交信息格式、文档语气  

### 不该记什么

- 一次性任务细节  
- 会过期的临时状态  
- 密钥、密码、完整凭证  

### 怎么管理

1. 侧栏打开 **记忆**  
2. 添加条目并选择分类（偏好、习惯、事实等）  
3. 用启用 / 停用控制是否注入后续对话  
4. 定期删除过时条目  

启用中的记忆会作为背景进入对话。条目越精、越准，越有用；又长又过时的记忆会干扰新任务。

当 Agent 写入记忆后，花 10 秒扫一眼是否该保留——这和审查 diff 一样重要。

## 知识库

### 适用材料

- 产品 / 设计规范  
- 内部流程与 runbook  
- 笔记库、导出的文档集  
- 需要反复引用、但不一定每次都改的目录  

不适合把「当前正在大改的整个 monorepo」只靠知识库代替项目工作区：要改代码请用 [项目](./projects)。

### 配置

1. 设置 → **知识库**  
2. 添加目录路径  
3. 配置 **Embedding**（推荐）：  
   - API 地址（OpenAI 兼容，可为本地 Ollama 等）  
   - 模型名（如 `nomic-embed-text`、`text-embedding-3-small`）  
   - API Key（本地服务常可留空）  
4. 等待索引完成，确认文件数 / 文本块数合理  

关闭 Embedding 时，检索能力下降；这不是静默成功，效果会差到你能感觉到。

### 在目标里引用

写明范围，减少模型「自由发挥」：

```
根据知识库中与「发布流程」相关的文档，列出上线检查清单。
用分组 bullet；每条注明依据的文档主题。不要编造未索引的流程。
```

## 和「写在提示里」怎么选

| 信息类型 | 建议 |
|---|---|
| 跨任务稳定 | 记忆 |
| 大段可检索资料 | 知识库 |
| 仅本次有效 | 写在当前目标 |
| 固定作业流程 | Skill |

# 控制任务

执行过程中，你始终可以中止、确认、纠偏。下面按场景说明。

## 停止

任务处于执行中时，使用输入区 **停止**。  
停止后任务进入已取消（或相应结束状态），不再继续调用工具。

适用：方向明显跑偏、误触发送、发现正在改不该动的路径。

## 审批与追问

见 [权限与审批](./permissions)。摘要：

- **等待确认** → 允许本次 / 拒绝  
- **等待补充信息** → 在对话中回答追问后继续  

## 编辑消息并重试

目标写错、范围写窄、交付格式不对时，优先编辑重试，而不是堆很长的「其实我是想…」。

1. 在已发送的**用户消息**上选择编辑  
2. 在气泡内改文案（可保留原附件策略以界面为准）  
3. 发送：回退到该点并以新内容继续  
4. 若继续失败，可用 **撤销编辑** 恢复  

任务运行中编辑入口可能不可用：先停止或等当前轮结束。

这相当于「改需求重跑」，比新开对话再粘贴一长段历史更干净。

## 分支

**从此分支**会基于某条消息的上下文创建新任务并切换过去。

适用：

- 保留原方案，另试一条实现路线  
- 探索性改动不想污染主对话  

不适合：同一目标的微小措辞修正（用编辑重试即可）。

## 压缩上下文

对话变长后，模型有效注意力下降。使用 **`/compact`**（或界面中的压缩入口）将旧消息收成摘要。

注意：

- 早期原文细节可能变少  
- 压缩后把**硬约束**再写进一条新消息  
- 稳定偏好应进 [记忆](./memory)，而不是只靠超长对话记住  

## 预算用尽

任务有两层预算（设置里可调，仅影响**之后新建**的任务）：

| 层 | 含义 |
|---|---|
| **单次执行** | 一次用户发言或恢复后的一轮工作 |
| **任务寿命** | 跨续聊、多次恢复的累计上限 |

可限制回合数、工具调用次数、运行时间等。触顶后常见处理：

- 编辑消息缩小范围后重试  
- 在允许时 **恢复** 继续  
- 拆成新对话，避免一条任务无限续命  

预算是保险丝，用来防止失控循环与意外账单（模型费用仍取决于你的 Provider）。

## 续聊

同一任务内继续发消息，会在已有上下文上推进（空闲时开新一轮；运行中可能作为 steering / follow-up，以产品行为为准）。  
新话题、新仓库：开新对话或换项目，不要硬续。

## 失败之后

失败卡片会给出类别倾向（配置、模型、工具、权限、超时、预算等）。按类别：

1. 配置 / 模型 → 查 Key、Base URL、模型启用  
2. 权限 → 审批是否拒绝、终端是否关闭  
3. 工具 → 路径是否存在、网络是否可达  
4. 预算 / 超时 → 缩小任务或调预算  

详见 [故障排查](./troubleshooting)。

# 设置

设置按分类组织。这里说明**会影响行为**的项；界面文案以当前版本为准。

改完设置后点各页的 **保存**，或标题栏 **保存并刷新**（先写入当前草稿，再从 Agent 重载）。外观与语言等本地偏好改完即生效。提供商连接使用连接区的「保存连接」。

改完模型与权限后，用一条小任务验证，再加大任务难度。

## 常规

### 工作模式

| 模式 | 效果 |
|---|---|
| 适用于编程 | 默认展示更多工具与轨迹细节 |
| 适用于日常工作 | 默认收起细节，优先结论与轻量进度 |

### 权限

| 选项 | 建议 |
|---|---|
| 允许运行终端命令 | 默认关；可信仓库且确实需要时再开 |
| 自动模式安全规则 | 默认开；勿在不了解风险时关闭 |

详见 [权限与审批](./permissions)。

### 任务预算

两层限制，防止单次或累计失控：

| 层 | 控制什么 |
|---|---|
| 单次执行 | 一次发言 / 恢复内的回合、工具次数、墙钟时间 |
| 任务寿命 | 整个任务跨续聊的累计上限 |

仅作用于**此后新建**的任务。触顶后的处理见 [控制任务](./control#预算用尽)。

### 工具执行策略

| 策略 | 特点 |
|---|---|
| 并行 | 多工具轮次可能更快 |
| 顺序 | 更易预测，便于逐步审批与调试 |

调试陌生流程时用顺序；确认稳定后再考虑并行。

### 出站代理

仅作用于 **Agent 引擎** 的外网请求（订阅登录 OAuth、模型 API、网页搜索等），**不会**自动读取 Windows/macOS「系统代理」。

| 选项 | 说明 |
|---|---|
| 启用出站代理 | 开启后 Node `fetch` 经填写的代理访问外网 |
| 代理地址 | 仅 **HTTP**：`http://127.0.0.1:7890`（Clash 的 HTTP / mixed 端口）。**不支持** `socks5://` |
| 不走代理 | 逗号分隔主机；默认绕过 `localhost` |
| 测试连接 | 保存设置后探测 `auth.x.ai`；失败时检查代理是否开启 |

在仅开启系统代理、未在此填写地址时，浏览器里的 OAuth 页面可能正常，但 xAI device-code 等 **Agent 侧请求** 仍会 `fetch failed`。TUN/全局 VPN 可替代本设置。

### 推理深度

也可在输入框切换。仅对支持 thinking / reasoning 的模型有意义。见 [如何写目标](./prompting#推理深度)。

### 关于与更新

桌面应用会从 [GitHub Releases](https://github.com/nullskymc/Aurevoy/releases) 检查新版本：

1. 启动后静默检查；有更新时 toast 提示  
2. 在本页可手动 **检查更新** / **下载并安装**  
3. 安装完成后应用会重启  

浏览器开发模式无此能力。维护说明见 [自动更新](/dev/auto-update)。

## 提供商与模型

1. 配置 Provider：类型、Base URL（可选）、API Key  
2. 启用要在主界面出现的模型  
3. 在对话输入区选择当前模型  

常见问题：「有 Key 但发不了」→ 模型未启用，或选中了未配置 Key 的 Provider。

> **DeepSeek 官方接入**：全量模型统一走官方 [Responses API](https://api-docs.deepseek.com/zh-cn/guides/responses_api)（`/responses`），不再使用旧式 Chat Completions。
> 个别模型在官方开放前调用会收到上游明确错误（如 `deepseek-v4-pro` 预计 2026 年 8 月初开放），不会降级到旧协议。
> 第三方网关（非官方主机）挂 DeepSeek 模型时仍按网关能力走 Chat Completions。

## 搜索

开启 **优先使用 API 原生搜索** 后，Aurevoy 会按当前实际协议自动尝试服务器搜索：

- Responses API（包括兼容端）使用托管 `web_search`；DeepSeek 官方 Responses 端点同样支持服务器搜索。
- Anthropic Messages API 使用服务器 Web Search。
- DeepSeek 官方模型全量走 Responses API，原生搜索使用服务器 `web_search`；上游拒绝时自动回落下方本地搜索后端。
- 上游不支持相应工具或协议时，自动回退原协议与下方配置的本地搜索后端。
- 对话过程只显示“正在搜索网页 / 已搜索网页”等工具状态；重启后从会话消息恢复，不展示 Provider 的内部搜索载荷。
- 服务器搜索可能由模型服务商单独计费；具体以服务商说明为准。

关闭该开关或发生自动回退时，Aurevoy `web_search` 函数工具使用这里配置的后端：

| 选项 | 说明 |
|---|---|
| DuckDuckGo Lite | 免费、无需 Key；可能被限流 |
| Tavily / SearXNG / 自定义 | 更稳定；需 Key 或自建地址 |

调研任务再依赖搜索；失败时检查限流与 API 配置，而不是无限重试同一提示。

## MCP 服务器

接入后外部工具出现在工具列表。设置页可新增、编辑、启停和删除服务器，并显示真实的连接状态、错误与工具数量。

- **本地 stdio**：填写命令、参数；按需补充工作目录和环境变量。
- **远程 Streamable HTTP**：填写服务 URL；需要认证时可加请求头。
- 只添加能去掉真实手工步骤的服务器  
- 连接失败应显示不可用  
- 高风险外部工具仍走审批逻辑  

点击 **测试连接** 会启动一次性客户端并列出工具数量，不会保存或注册配置；确认可用后再点击 **保存**。保存后引擎会重载 MCP；单个服务器连不上不会阻断其它服务器或本地 Agent 启动。敏感 header/env 会进入本机 SQLite 凭据表，设置页只保留脱敏占位符。推荐模板默认停用，只预填官方参考服务的结构化配置，使用前请替换路径/URL并重新确认风险。模板参考：[MCP filesystem server](https://github.com/modelcontextprotocol/servers/blob/main/src/filesystem/README.md)、[MCP everything server](https://github.com/modelcontextprotocol/servers/blob/main/src/everything/README.md)。

浏览器 MCP 返回的截图、DOM 文本和下载 resource 会按大小上限保存到当前工作区的 `.aurevoy/browser-artifacts/`，作为带“外部不可信”标记的文件或图片块出现在对话中，可直接打开工作台；写入失败只影响产物交付，不会伪装成浏览器调用成功。

### Skill 安装

在左侧 **Skill** 页面安装 Git 仓库中的 Skill 时，需要同时填写：仓库 URL、已经检查过的 Skill 路径、检查来源（可选）和检查依据摘要。路径可以写目录（例如 `skills/research`）或 `SKILL.md` 路径；摘要至少 20 个字符。Aurevoy 只会安装这些已确认路径，不会因为仓库中还有其他 `SKILL.md` 就一并加载；安装后的来源与依据会保存在本地元数据中，重复安装会明确显示已存在的 Skill。

先在浏览器或仓库页面检查 `SKILL.md`、工具权限和脚本，再把实际路径与检查结论粘贴到表单。不要把 API Key、Cookie 或其他秘密写入摘要；仓库来源只能使用 HTTP(S) 或 SSH Git 地址。

如果 MCP 服务名包含 `playwright` 或 `browser`，编辑器会额外显示浏览器权限模板：**只读研究**、**允许下载**、**允许登录**、**允许提交**。未选择时运行时按只读处理，被模板拦截的工具不会注册给模型；提高模板后仍需逐次显式审批。连接状态会显示已注册工具和被模板拦截的工具数量。

### 浏览器 Skill

打开左侧 **Skill** 页面即可看到 **浏览器运行时** 卡片。它会显示 browser Skill 是否启用、Playwright MCP 是否配置/连通、已注册工具和被模板拦截的工具；**测试连接** 只建立一次性探测，不安装依赖、不打开网页、不保存配置。未配置时按卡片提示安装 `@anthropic/mcp-server-playwright`，再在 MCP 设置中添加 stdio command/args。浏览器导航、读取、截图、下载和表单提交仍受工具审批与风险规则约束，运行时显示“就绪”不代表高风险动作会自动执行。

浏览器步骤失败时，任务失败卡片会区分登录态缺失、页面变化、元素失效和下载失败；可恢复的任务会显示重试，检测到页面地址时可打开已去掉 query/hash 的脱敏页面，也可以复制不含常见秘密字段的人工处理摘要。摘要入口用于人工接管，不会替代审批或静默重试。

## 本地数据与用量

- **健康诊断**：进入 **设置 → 本地数据** 后会检查 LLM、SQLite、工作区、Embedding、sqlite-vec 与知识库索引；诊断只检查本机状态，不会主动调用上游模型。点击 **刷新** 可重新探测。
- **数据导出**：默认下载任务、记忆、项目元数据和配置状态的脱敏 JSON。勾选 **包含任务消息正文** 才会带上当前/归档消息；用户目标、计划、记忆和消息正文仍可能含隐私，分享前先打开 JSON 检查。
- **数据清理**：填写保留天数并点击 **清理**，确认后只删除超过期限的 `completed` / `failed` / `cancelled` 任务；运行中、暂停中和期限内任务保留。关联轨迹、图片分片与 Pi 会话树会一起删除，无法撤销。
- **Token 统计**：观察调用规模，便于控制成本  

## 自动化

从左侧 **自动化** 打开 **已安排的任务** 页面：

1. 使用搜索框和 **全部 / 已开启 / 已暂停** 筛选，快速定位已有任务。
2. 点击右上角 **创建**，选择新建任务或从建议模板开始；在弹窗中填写目标、项目、频率和执行模式后保存。
3. 页面下方的建议包含每日简报、每周回顾和跟进监控，点击后会预填配置，但仍需确认模型/预算/权限边界后保存。
4. 任务行支持立即运行、打开最近任务、查看运行记录、启用或暂停；已经创建的任务不会因暂停配方而删除。
5. 勾选“已确认当前全局模型、预算与审批边界”后才可 **先试跑** 或保存；试跑使用真实 Agent 任务但不写入配方，成功后可从弹窗打开任务，失败时草稿仍保留。

已完成的对话会显示 **设为自动化**。点击后只继承该对话的目标和项目，执行模式、启用状态、运行频率以及单次/累计预算必须在新草稿中重新确认；试跑同样使用这份新预算。

自动化不拥有独立的执行后端，不会绕过工具审批、预算限制或 auto 安全门。任务需要确认时会停在原任务里，Agent 重启后会从本地 SQLite 恢复配方和未收敛的运行记录。

卸载或迁移前，先使用数据导出备份；导出结构化字段不会包含 API Key、OAuth、MCP JSON、代理地址或本地路径，但用户文本可能包含路径和其他隐私。

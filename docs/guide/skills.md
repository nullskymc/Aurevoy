# Skill

Skill 把**可重复的工作方式**打包成可启用的能力单元：名称、说明、流程与工具边界。  
适合「每次都要交代同一套做法」的任务，而不是一次性的随口需求。

## 什么时候用 Skill

| 适合 | 不适合 |
|---|---|
| 固定流程（发布检查、日志归类、调研模板） | 只会出现一次的临时问题 |
| 需要特定工具组合（搜索 + 浏览器等） | 用普通目标一句话说清即可的小事 |
| 希望团队 / 未来的自己同一套标准 | 把整个产品说明书塞进一个 Skill |

经验法则：同一段提示你纠正了两次，就该考虑做成 Skill（或写进记忆）。

## 在对话里调用

1. 在输入框输入 **`/`**  
2. 选择 Skill  
3. 用自然语言补全**本次**的具体目标、路径与完成标准  

Skill 提供方法与能力边界；**本次变量**（哪个仓库、哪次事故、哪份材料）仍要写在目标里。见 [如何写目标](./prompting)。

## 管理 Skill

侧栏打开 **Skill** 页：

| 操作 | 说明 |
|---|---|
| 启用 / 停用 | 停用后不会出现在可选列表 |
| 从 Git 安装 | 粘贴仓库 URL（需网络） |
| 重载 | 重新扫描已安装内容 |
| 卸载 | 移除可卸载的用户 / 系统 Skill |

来源可能包括内置、用户安装、系统、工作区等，界面会标注分类。

## 设计良好的 Skill（给你自己或仓库）

若你维护 Skill 仓库或本地 Skill：

1. **一件事一个 Skill**，描述写清「做什么 / 何时用」  
2. 写清输入输出与完成标准，而不是堆砌全部边缘情况  
3. 先用一个代表任务跑通，再扩展  
4. 只在能提高稳定性时附脚本或额外资源  

与 MCP 的分工：MCP 连接外部系统；Skill 描述**怎么用这些能力完成一类工作**。两者可叠加，但权限与审批仍然生效。

## 与工具、MCP

| 能力 | 角色 |
|---|---|
| 内置工具 | 文件、网络等基础动作 |
| Skill | 场景化流程与说明 |
| MCP | 扩展外部工具源 |

设置里管理 MCP 连接；失败时应明确不可用，而不是假装调用成功。

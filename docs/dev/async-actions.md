# 异步动作反馈

所有会等待网络、引擎、文件系统或平台 API 的用户动作都需要同时满足：

1. pending 状态会锁住重复触发，并在按钮、行或状态区显示正在处理。
2. 成功后保留结果或状态变化；不能只依赖一个短暂 toast 证明动作完成。
3. 失败留在触发动作附近，给出可理解的错误或下一步；必要时由父层 toast 补充，但不能只吞掉异常。

源码契约由以下命令审计：

```bash
npm run audit:async-actions
```

该命令只防止状态反馈锚点在重构中消失；实际时序由组件测试、Agent 回归和 UI smoke 验证。需要用户继续处理的任务错误仍应留在任务/设置项内，toast 只承担短暂的全局反馈。

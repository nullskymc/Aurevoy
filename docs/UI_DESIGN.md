# 人机交互与前端界面设计 — UI_DESIGN

> 本文描述 Aurevoy 的智能体产品形态、桌面端信息架构、核心交互流与前端落地边界。
> 目标是把 Aurevoy 从“聊天输入页”推进为“个人 Agent 工作台”。

## 1. 设计目标

Aurevoy 的界面不应以传统聊天机器人为中心，而应以“用户目标 → Agent 计划 → 工具执行 → 结果交付”为中心。
用户只需要描述目标，界面负责持续解释 Agent 正在做什么、下一步是什么、哪里需要用户介入，以及最终产出了什么。

核心体验原则：

1. **目标优先**：首屏聚焦用户想完成的事情，而不是提示词技巧或模型参数。
2. **过程透明**：规划、步骤状态、工具调用、结果与错误都必须可见。
3. **用户可控**：长任务应提供停止订阅、重试、后续取消/暂停/继续等控制入口。
4. **本地可信**：明确展示本地 Agent 引擎状态、工具目录与运行上下文。
5. **长期可用**：采用克制、低干扰、高信息密度的桌面生产力风格。

## 2. 产品形态

### 2.1 Aurevoy 是目标驱动的 Agent 工作台

Agent 的主要职责不是即时回答，而是推动任务完成。界面要避免把所有信息塞进聊天气泡，应围绕一个任务生命周期组织信息：

1. 用户输入自然语言目标。
2. Agent 创建任务并进入规划。
3. Agent 展示计划步骤。
4. Agent 按步骤执行，必要时调用工具。
5. Agent 输出结果，并保存到任务历史。
6. 用户可回看、重试或基于结果继续推进。

### 2.2 Agent 状态模型

界面应使用用户可理解的状态标签映射 `TaskStatus`：

| 契约状态 | 展示文案 | UI 含义 |
|---|---|---|
| `pending` | 等待中 | 任务已创建，等待执行事件 |
| `planning` | 正在规划 | Agent 正在理解目标和拆解计划 |
| `running` | 执行中 | Agent 正在生成输出或调用工具 |
| `paused` | 等待确认 | Agent 需要用户输入或权限确认 |
| `completed` | 已完成 | 任务成功结束 |
| `failed` | 失败 | 执行出错，需要重试或调整 |
| `cancelled` | 已取消 | 用户主动终止任务 |

## 3. 信息架构

桌面端采用三栏工作台结构：

```text
┌───────────────┬─────────────────────────────────┬──────────────────┐
│ 左侧栏         │ 中央工作区                        │ 右侧检查器        │
│ 导航/历史       │ 目标输入/计划/结果                 │ 工具/事件/上下文   │
└───────────────┴─────────────────────────────────┴──────────────────┘
```

### 3.1 左侧栏：任务与导航

左侧栏用于建立“这是一个可持续工作的个人 Agent”的产品心智。

必须包含：

- 品牌与产品定位：Aurevoy / 个人 Agent 工作台。
- 主导航：工作台、工具、记忆、设置。
- 今日任务与已完成统计。
- 任务历史列表，按更新时间倒序。
- 每条历史展示目标摘要、状态和相对时间。

### 3.2 中央工作区：目标与交付

中央工作区是主操作区，所有关键任务流都在这里完成。

必须包含：

- 页面标题：目标驱动执行台。
- 当前状态标签。
- 重试与停止订阅入口。
- Goal Composer：自然语言目标输入、建议目标、开始执行按钮、引擎在线状态。
- 当前任务概览：当前目标、计划步骤数、输出长度。
- Plan Timeline：计划步骤和每步状态。
- Result：流式输出与最终结果，独立滚动，避免内容增长挤压布局。

### 3.3 右侧检查器：透明度与调试

右侧检查器用于解释 Agent 的内部运行情况，默认面向高意愿用户和调试场景。

必须包含：

- 任务上下文：当前目标、消息数、引擎运行时长。
- 工具目录：来自 `GET /api/tools` 的工具列表。
- 工具调用：展示 `tool_call` 和 `tool_result`。
- 事件流：展示非 token 级别的关键事件，辅助理解执行过程。
- 可折叠能力：中等窗口下可收起，窄窗口下隐藏。

## 4. 核心工作流

### 4.1 引擎探测

应用启动时并行请求：

- `GET /api/health`
- `GET /api/tasks`
- `GET /api/tools`

成功后：

- Goal Composer 显示“引擎在线”。
- 设置区显示引擎版本。
- 工具目录展示已注册工具。
- 若存在历史任务，默认选中最新任务。

失败后：

- Goal Composer 显示“引擎离线”。
- 开始执行按钮禁用。
- 工具数和运行时长显示离线状态。

### 4.2 创建任务

用户提交目标时：

1. 前端调用 `POST /api/tasks { goal }`。
2. 立即清空上一任务的临时计划、输出和事件流。
3. 将返回的 `Task` 插入任务历史顶部。
4. 通过 `EventSource` 订阅 `/api/tasks/:id/stream`。
5. 按事件增量更新 UI。

### 4.3 事件消费

前端必须完整消费现有 `AgentEvent`：

| 事件 | 前端行为 |
|---|---|
| `task_created` | 设置当前任务，刷新历史与快照 |
| `status` | 更新状态标签 |
| `plan` | 渲染完整计划 |
| `step_update` | 更新单个计划步骤 |
| `token` | 追加到结果区 |
| `message` | 合并消息，避免按 id 重复插入 |
| `tool_call` | 写入事件流与工具调用区 |
| `tool_result` | 写入事件流与工具调用区 |
| `done` | 设置最终状态，关闭 EventSource，刷新历史 |
| `error` | 展示错误文案，停止忙碌态 |

### 4.4 SSE 快照回放

Mock 引擎执行很快，前端可能在订阅前错过早期事件。后端 SSE 端点应在新订阅建立后先补发数据库快照：

1. `task_created`
2. `status`
3. `plan`（如已有）
4. 已保存 `message`
5. 若任务已结束，补发 `done`

这样前端刷新、迟到订阅或历史回看时都能恢复任务状态。

### 4.5 用户控制

当前阶段前端提供：

- **重试**：用当前目标创建一个新任务。
- **停止订阅**：关闭当前 EventSource，只停止前端接收，不声称已经取消后端任务。

后续完整控制能力应按契约优先原则新增：

- `POST /api/tasks/:id/cancel`
- `POST /api/tasks/:id/pause`
- `POST /api/tasks/:id/resume`

对应请求/响应类型必须先定义在 `packages/shared/src/`。

## 5. 视觉系统

### 5.1 方向

视觉方向采用“专业克制”的桌面生产力风格：

- 浅色优先，深色跟随系统。
- 中性色为主，单一蓝色强调当前操作与运行状态。
- 绿色仅用于完成或可用状态。
- 红色仅用于错误、失败和取消。
- 避免大面积渐变、营销式 hero、漂浮装饰和过度圆角。

### 5.2 布局纪律

- 页面固定占满窗口高度。
- 左侧栏、中央工作区、右侧检查器各自独立滚动。
- 结果区固定在独立面板内滚动，避免 token 增长导致整体跳动。
- 卡片半径不超过 8px。
- 文本必须在容器内截断或换行，不允许溢出覆盖邻近内容。

### 5.3 响应式

| 宽度 | 行为 |
|---|---|
| 宽窗口 | 显示左侧栏、中央工作区、右侧检查器 |
| 中等窗口 | 右侧检查器收起为窄栏 |
| 窄窗口 | 左侧栏收敛为图标导航，右侧检查器隐藏，中央工作区单列显示 |

## 6. 前端组件边界

推荐组件拆分：

| 组件 | 职责 |
|---|---|
| `App` | 应用状态编排、健康检查、SSE 生命周期、任务历史 |
| `TaskHistorySidebar` | 左侧导航、任务统计和历史选择 |
| `TaskWorkspace` | 中央工作区框架 |
| `GoalComposer` | 目标输入、建议目标、提交入口 |
| `PlanTimeline` | 计划步骤展示 |
| `AgentEventFeed` | 事件流展示 |
| `InspectorPanel` | 右侧上下文、工具、调用与事件检查器 |
| `SettingsPanel` | 运行状态、Provider、工具和记忆摘要 |
| `StatusPill` | 任务状态标签 |

`App` 可以持有 UI 编排状态，但业务真相仍来自后端 `Task` 和 `AgentEvent`。

## 7. 接口与契约边界

必须遵守：

- 跨进程数据结构只从 `@aurevoy/shared` 导入。
- 前端请求只通过 `apps/desktop/src/lib/api.ts`。
- 新增任务控制类 API 时，先改 `packages/shared/src/`，再联动 agent 与 desktop。
- 工具展示必须来自 `GET /api/tools`，不要在前端硬编码工具目录。
- API Key、Provider 配置等敏感信息不得硬编码到前端。

## 8. 验收标准

基础验收：

- `npm run typecheck` 通过。
- 前端改动后 `npm run build -w @aurevoy/desktop` 通过。
- 引擎离线时，界面显示离线并禁用开始执行。
- 引擎在线时，界面显示版本、工具数和工具目录。
- 创建任务后能展示计划、状态、结果和事件流。
- 收到 `done` 后关闭 EventSource，并刷新任务历史。
- 历史任务可选中回看。

界面验收：

- 宽窗口显示三栏。
- 中等窗口右侧检查器可收起。
- 窄窗口隐藏检查器，左侧栏折叠，中央工作区不出现横向溢出。
- 长结果输出不会挤压计划区或检查器。
- 所有按钮和状态文案使用中文，符合普通个人用户理解。
